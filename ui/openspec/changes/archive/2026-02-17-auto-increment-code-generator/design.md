## 上下文

需要一个公共的 Code 生成器服务，可以被租户、权限、角色等服务复用。code 格式为"前缀+6位数字"，如 P000001, T000001, R000001。

## 目标 / 非目标

**目标：**
- 提供通用方法 `GenerateCode(currentMaxCode, prefix)`
- 支持 Redis 分布式锁（首选）
- Redis 不可用时降级到内存缓存
- 支持循环（999999 后回到 000001）

**非目标：**
- 不修改现有业务接口
- 不涉及数据库操作

## 决策

### 方案 A：每次调用时解析 currentMaxCode
- 优点：调用方传入当前最大码，逻辑简单
- 缺点：需要调用方查询当前最大码

### 方案 B：在服务内部维护缓存
- 优点：调用方无需关心
- 缺点：需要维护缓存，增加复杂度

**选择方案 A**，由调用方传入当前最大 code，服务负责解析和自增。

### 缓存策略
- 首选 Redis：使用 Redis 的 INCR 操作保证原子性
- 降级方案：使用 sync.Mutex 保护内存变量

## 风险 / 权衡

- 并发安全：需要确保多实例场景下的原子性
- 循环重置：999999 后需要重置为 000001
