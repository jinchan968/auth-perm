## 上下文

当前前端项目中，不同页面使用不同的标题格式：
- 首页/登录页：`Auth-Perm`（品牌名）
- 列表页：`权限列表`、`角色列表`、`租户管理`（功能名 + 列表/管理）
- 详情页：`权限详情`（功能名 + 详情）

这种不一致导致用户体验不佳，需要统一规范。

## 目标 / 非目标

**目标：**
- 定义统一的页面标题格式规范
- 创建可复用的页面标题组件
- 迁移现有页面到统一格式

**非目标：**
- 不修改后端 API
- 不改变现有页面功能逻辑

## 决策

### 1. 标题格式

采用 `{页面名称} - {品牌名}` 格式：
- 首页：`Auth-Perm`
- 列表页：`权限列表 - Auth-Perm`
- 详情页：`权限详情 - Auth-Perm`

**理由：** 这种格式在浏览器标签页和导航中都很常见，用户易于理解。

### 2. 实现方式

在每个页面组件中统一使用 `<h1>` 标签显示页面标题，品牌名在右侧显示。

**理由：** 不需要创建额外的组件，利用现有的 UI 结构即可实现。

### 3. 路由与标题映射

通过路由路径自动推断页面标题：
- `/home` → 首页
- `/permissions` → 权限列表
- `/permissions/[id]` → 权限详情
- `/permissions/roles` → 角色列表
- `/tenants` → 租户管理
- `/tenants/[id]` → 租户详情

**理由：** 使用映射表可以集中管理，易于维护和扩展。

## 风险 / 权衡

- **动态路由标题**：对于 `/permissions/[id]` 这类动态路由，需要从 API 获取数据后才能显示正确标题。
  - 缓解：在数据加载前显示通用标题，加载后更新。

- **面包屑导航**：现有面包屑组件已经处理了导航结构。
  - 缓解：页面标题与面包屑保持一致即可。
