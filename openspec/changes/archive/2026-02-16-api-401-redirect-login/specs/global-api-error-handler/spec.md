## 新增需求

### 需求:全局 401 错误处理
API 客户端必须全局捕获 401 Unauthorized 响应，并自动将用户重定向到登录页面。

#### 场景:API 返回 401 时重定向到登录页
- **当** 前端调用任何 API 时，后端返回 HTTP 401 状态码
- **那么** 系统必须清除 localStorage 中的认证信息 (auth_token, auth-storage)
- **那么** 系统必须清除 Zustand auth store 中的用户状态
- **那么** 系统必须将页面重定向到 `/login`

#### 场景:排除公开路由不进行重定向
- **当** 用户当前位于 `/login` 或 `/register` 等公开路由
- **那么** 即使收到 401 响应，也不执行重定向

### 需求:认证状态清除
系统必须在重定向前清除所有认证相关状态。

#### 场景:清除 localStorage
- **当** 收到 401 响应
- **那么** 必须清除 `auth_token` 项
- **那么** 必须清除 `auth-storage` 项

#### 场景:清除 Zustand Store
- **当** 收到 401 响应
- **那么** 必须调用 authStore 的 logout 方法清除状态

### 需求:SSR 兼容性
系统必须在服务端渲染环境下安全处理。

#### 场景:客户端环境执行重定向
- **当** 收到 401 响应且运行在浏览器环境
- **那么** 执行重定向逻辑

#### 场景:服务端环境不执行重定向
- **当** 收到 401 响应且运行在服务端
- **那么** 不执行重定向（避免 SSR 错误）
