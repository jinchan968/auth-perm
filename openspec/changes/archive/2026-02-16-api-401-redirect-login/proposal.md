## 为什么

当前前端调用 API 时，如果后端返回 401 Unauthorized，用户不会被重定向到登录页面，导致用户体验不佳。用户可能会停留在当前页面而不知道会话已过期，需要手动刷新页面才能重新登录。

## 变更内容

- 创建全局 API 错误处理机制
- 在 API 客户端拦截 401 响应
- 401 响应时清除本地存储的认证信息并重定向到登录页面

## 功能 (Capabilities)

### 新增功能
- **global-api-error-handler**: 全局 API 错误处理和 401 重定向

### 修改功能
（无）

## 影响

- 前端 API 客户端 (`lib/api/client.ts`)
- 可能需要修改认证 store 以支持清除状态
- 路由中间件（如需要）
