# 租户禁用功能 - 技术设计

## 上下文

将租户的删除操作改为禁用操作，保留数据便于审计和恢复。

## 目标 / 非目标

**目标：**
- 将租户删除改为禁用（更新状态为 suspended）
- 查询租户时默认排除已禁用的租户
- 前端支持禁用/启用操作

**非目标：**
- 不实现租户的物理删除
- 不修改其他业务逻辑

## 决策

### 后端实现
1. **修改 Delete 接口**：将 `db.Delete()` 改为 `UpdateStatus(suspended)`
2. **添加 Enable 接口**：新增启用租户接口，更新状态为 active
3. **修改查询逻辑**：List 时默认添加 `status != suspended` 条件

### 前端实现
1. **修改按钮**：将"删除"改为"禁用"
2. **添加启用按钮**：已禁用的租户显示"启用"按钮

### API 设计
- DELETE /api/v1/tenants/:id → 禁用租户（更新状态）
- PUT /api/v1/tenants/:id/enable → 启用租户（可选）

## 风险 / 权衡

- 数据保留：禁用后数据仍存在于数据库，需要定期清理策略
- 状态一致性：需要确保所有查询都正确处理 suspended 状态
