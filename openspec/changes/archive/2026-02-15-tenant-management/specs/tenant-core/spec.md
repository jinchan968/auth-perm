# tenant-core 规范

## 新增需求

### 需求:租户可以被创建
系统必须支持创建新的租户。

#### 场景:成功创建租户
- **当** 管理员提交租户名称、代码和套餐信息
- **那么** 系统创建租户记录并返回租户信息

#### 场景:租户代码重复
- **当** 管理员提交一个已存在的租户代码
- **那么** 系统返回错误提示租户代码已存在

### 需求:租户可以被查询
系统必须支持根据ID查询租户详情。

#### 场景:查询存在的租户
- **当** 管理员请求查询指定ID的租户
- **那么** 系统返回租户的完整信息

#### 场景:查询不存在的租户
- **当** 管理员请求查询一个不存在的租户ID
- **那么** 系统返回错误提示租户不存在

### 需求:租户可以被更新
系统必须支持更新租户的基本信息。

#### 场景:更新租户名称
- **当** 管理员提交租户名称更新
- **那么** 系统更新租户名称并返回更新后的信息

#### 场景:更新租户状态
- **当** 管理员提交租户状态变更（启用/停用）
- **那么** 系统更新租户状态

### 需求:租户可以被删除
系统必须支持删除租户（软删除）。

#### 场景:删除租户
- **当** 管理员请求删除指定租户
- **那么** 系统标记租户为已删除状态

### 需求:租户列表查询
系统必须支持分页查询租户列表。

#### 场景:分页查询租户
- **当** 管理员请求租户列表并指定分页参数
- **那么** 系统返回指定页的租户列表和总数
