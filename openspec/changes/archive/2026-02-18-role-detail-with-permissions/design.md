# 角色详情接口优化 - 技术设计

## 上下文

当前角色详情接口 `GET /api/v1/permissions/roles/:id` 在返回时出现错误，原因是查询角色与权限关联关系时返回空结果。用户需要在获取角色详情时，同时看到：
1. 租户下全量的权限列表
2. 角色已关联的权限
3. 由后端标记已关联的状态，前端直接根据状态展示勾选

## 目标 / 非目标

**目标：**
- 修改 `GetRole` 方法，返回角色详情时同时返回全量权限列表
- 每个权限添加 `is_selected` 标记，表示是否已关联到该角色
- 保持 API 向后兼容

**非目标：**
- 不修改角色列表接口（ListRoles）
- 不修改权限分配的其他接口

## 决策

### 方案：扩展 RoleDTO 增加权限列表字段

在 `RoleDTO` 中添加 `Permissions` 字段，返回权限列表。区别于已有的 `PermissionCount`（仅数量），新增字段返回完整权限对象列表。

每个权限对象需要添加 `is_selected` 标记来标识是否已关联。

**选择理由：**
- 前端可以直接使用 `is_selected` 判断勾选状态
- 减少前端处理逻辑
- 保持返回结构清晰

**备选方案：**
- 返回两个列表（已关联、未关联）- 增加复杂度，不采用

## 风险 / 权衡

- 性能考虑：查询全量权限可能影响响应速度
  - 缓解：仅在详情接口返回，列表接口保持原有逻辑
- 数据量：租户下权限数量可能较大
  - 缓解：权限通常数量有限，影响可控
