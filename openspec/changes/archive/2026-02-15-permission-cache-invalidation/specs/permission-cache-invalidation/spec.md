## 新增需求

### 需求:权限缓存必须设置合理的 TTL

系统必须将用户权限缓存的 TTL 设置为不超过 10 分钟，以确保权限变更后用户能够在合理时间内获得最新权限。

#### 场景:缓存 TTL 配置
- **当** 系统配置权限缓存时
- **那么** TTL 必须设置为 10 分钟或更短

#### 场景:缓存自动过期
- **当** 缓存超过 TTL 时间后
- **那么** 缓存自动失效，后续请求需重新从数据库加载

### 需求:权限变更时必须主动失效缓存

当发生角色创建、修改、删除或权限分配/回收操作时，系统必须主动失效相关用户的权限缓存，确保权限变更立即生效。

#### 场景:角色删除时失效缓存
- **当** 管理员删除一个角色
- **那么** 系统必须失效所有拥有该角色的用户的权限缓存

#### 场景:角色修改时失效缓存
- **当** 管理员修改角色的权限配置
- **那么** 系统必须失效所有拥有该角色的用户的权限缓存

#### 场景:权限分配时失效缓存
- **当** 管理员给角色分配新权限
- **那么** 系统必须失效所有拥有该角色的用户的权限缓存

#### 场景:权限回收时失效缓存
- **当** 管理员从角色移除权限
- **那么** 系统必须失效所有拥有该角色的用户的权限缓存

#### 场景:用户角色分配时失效缓存
- **当** 管理员给用户分配新角色
- **那么** 系统必须失效该用户的权限缓存

#### 场景:用户角色移除时失效缓存
- **当** 管理员从用户移除角色
- **那么** 系统必须失效该用户的权限缓存

### 需求:缓存失效必须使用延迟双删策略

为避免缓存击穿，系统必须使用延迟双删策略失效缓存，即先删除缓存，延迟后再次删除。

#### 场景:双删机制执行
- **当** 触发缓存失效时
- **那么** 系统必须立即删除缓存，并在延迟后再次删除
